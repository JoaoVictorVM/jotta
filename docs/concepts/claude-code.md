# Claude Code adapter

Claude Code reads its configuration from `.claude/`. The adapter generates that configuration from the harness files, so hooks, roles and skills are active as soon as the project opens, without copying them by hand.

```bash
jotta adapter claude            # generate or refresh .claude/
jotta adapter claude --dry-run  # show what would change
```

`jotta install` runs the adapter after copying the harness.

## What is generated

| File | Source | Content |
|---|---|---|
| `.claude/settings.json` | Built in and `.jotta/policy/profile-permissions.json` | The `PreToolUse`, `PostToolUse` and `Stop` [hooks](./hooks.md), each calling `jotta hook <event>`, and the `Bash` permission rules of the active [profile](./profiles.md#permissions-per-profile). |
| `.claude/jotta-permissions.json` | `.jotta/policy/profile-permissions.json` | The permission rules the adapter added, so a profile change replaces them. |
| `.claude/agents/<role>.md` | `.jotta/agents/<role>.md` | A subagent with the role as its prompt and the role's first paragraph as its description. |
| `.claude/skills/<skill>/SKILL.md` | `.jotta/skills/<skill>/SKILL.md` | The skill's name and description, and an instruction to read the canonical file. |

Subagent tools follow the role:

| Role | Tools |
|---|---|
| `reviewer`, `qa-reviewer` | `Read`, `Grep`, `Glob`: they review and report, never edit. |
| `spec-author` | `Read`, `Grep`, `Glob`, `Write`, `Edit`, to write the spec and plan. |
| `implementer`, `orchestrator` | Every tool of the session. |

Skill entries point to the canonical skill instead of copying it, so the skill's relative references keep resolving and there is a single file to maintain.

## Merging with existing files

- **Settings.** The adapter adds each `jotta hook` command that is missing and keeps every other key and hook. It replaces the permission rules it added before with those of the active profile, and keeps every rule of yours. Running it again changes nothing. When `settings.json` is not valid JSON, or its `hooks` are not in the documented shape, it writes nothing and reports the error.
- **Agents and skills.** Generated files carry a `generated by jotta` marker and are refreshed from their source. A file without the marker belongs to the user: it is never overwritten and is reported in `skipped`.

The files under `.jotta/` remain the source. To change a role or a skill, edit it there and run `jotta adapter claude` again.
